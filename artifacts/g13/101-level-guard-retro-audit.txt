=== 3. THE LEVEL GUARD IS NOT THE DISCRIMINATOR AT THIS NOTE ===

At note 61 the guard is anti-correlated with correctness:

  h12  -34.3 dB   PASSES the guard   shift -9.3779 c   WRONG by 12 c
  h16  -40.6 dB   FAILS  the guard   shift +2.7375 c   right to 0.04 c

A partial having energy in it does not make the estimator read it correctly.
This is the same lesson as the tool's own docstring on h64 at note 36 ("a high
harmonic is not made usable by having energy in it"), now with the converse
demonstrated: a LOW harmonic is not made unusable by lacking it.

=== 4. WHY THE PER-CAPTURE SCREEN DID NOT CATCH h12, AND THIS IS THE
       INSTRUMENT RESULT ===

Per-capture cents at note 61, every 2nd capture, three repeats:

  asked h8    mode 0  -7.324 / -7.055 / -7.325   sd 0.75-1.31
              mode 1  -4.769 / -4.442 / -4.154   sd 0.70-0.86   shift +2.7794
  asked h12   mode 0  +5.495 / +5.058 / +5.478   sd 0.84-1.21
              mode 1  -4.650 / -4.592 / -2.937   sd 1.05-4.22   shift -9.4034
  asked h16   mode 0  +2.212 / +2.043 / +2.164   sd 0.32-0.57
              mode 1  +5.128 / +4.802 / +4.772   sd 0.37-0.52   shift +2.7611

h12's failure is TIGHT, not noisy: mode 0 reads +5.5 c with sd ~1.0 c and all
three repeats agreeing to 0.44 c. It is a consistent lock onto the wrong thing
on ONE ARM ONLY, and it therefore does NOT cancel in the arm difference.

`cmd_screen` compares each capture to its NOTE's OWN median harmonic
disagreement. When the estimator fails the SAME WAY on every capture of a
cell, the median moves with the failure and nothing exceeds it. Screen output
at note 61 h12: "dropped 0 flagged 0". At note 59 the same harmonic dropped 19
and flagged 2, so the screen is not blind in general; it is blind to a UNIFORM
failure.

  A screen referenced to its own population cannot see a bias that is
  uniform within that population.

This EXTENDS L122 rather than repeating it. L122 says an instrument built for
a difference is not an instrument for the value. The new part: the difference
does not always rescue you either. It cancels a per-(note,harmonic) bias only
when the bias is the SAME ON BOTH ARMS, and at h12/note 61 the two arms lock
differently, so the bias survives the subtraction.

=== 5. WHAT I FOUND IN MY OWN ERROR BUDGET, STATED PLAINLY ===

The published note 61 harmonic systematic 0.0430 c is the h8/h16/h32 spread.
h12 IS EXCLUDED FROM IT AND NO CRITERION FOR EXCLUDING IT WAS EVER STATED.

At note 72 the analogous exclusion IS stated and IS principled: h32 was
refused at -61.3 dB by the level guard, a rule built independently from note
99 (101-four-rows-and-the-law.txt, lines 3-6). At note 59, h12 was excluded
and the screen had visibly flagged it (19 dropped, 2 flagged), which is a
criterion even if it went unwritten. At note 61 NEITHER applies: the level
guard passes h12 at -34.3 dB and the screen reports it clean.

So on this one row an outlier variant was dropped from an error budget by
hand. That is the exact fault section 8 of my handoff tells a reviewer to
attack, found by looking.

The exclusion turns out to be CORRECT, for the reason established in 3 and 4
above and not for any reason available at the time. The number does not move.
What changes is that it now has a stated rule behind it:

  EXCLUSION RULE, to be applied to every future variant family:
  exclude a harmonic variant when its two arms disagree in BIAS, tested as a
  shift displaced from the family median by more than the family spread while
  its within-arm sd stays comparable to the family's. Level is NOT the test
  and neither is the per-capture screen. Record every exclusion with the
  number that triggered it.
